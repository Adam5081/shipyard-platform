# ⚓ SHIPYARD — платформа программы

Платформа программы «от идеи до продукта, который работает у клиента»: участник
собирает продукт сам с Claude Code внутри производственного пайплайна, рядом —
эксперты отрасли. Дизайн — в стиле Apple; игровой слой карты пути — пиксель-арт.

## Состав

| Файл | Назначение |
|---|---|
| `index.html` | Лендинг: путь проекта раскрывающимися станциями, 6 направлений сервисного пула, наши проекты, «кто мы», безопасность, тарифы Solo/Pro/Partner, Demo Day, FAQ |
| `app.html` + `assets/app.js` | Кабинет участника (SPA) |
| `assets/game.js` | Пиксельный движок: карта Астаны и превращение фото в персонажа |
| `assets/styles.css` | Общая дизайн-система |
| `server/` | Бэкенд без зависимостей: API + раздача статики |

## Карта пути — главный экран кабинета

Первое, что видит участник, — не список задач, а он сам на карте. Персонаж идёт
слева направо по террасам, поднимаясь к двери MVP; за спиной поднимается Астана
(Хан Шатыр, Байтерек, Нур-Алем, Ак Орда).

- **Персонаж из фото.** Участник загружает фото, оно превращается в мультяшный
  пиксельный спрайт 12×12 прямо в браузере (кадр по лицу, повышение насыщенности,
  квантование палитры). На сервер уходит только спрайт, исходное фото — никогда.
  Без фото собирается узнаваемый спрайт из имени.
- **Девять станций.** Клик по станции раскрывает миссию: зачем этот этап, задачи
  с галочками, артефакт недели и инструмент-награда.
- **Инструменты.** За закрытую станцию участник забирает инструмент (ключ,
  микрофон, чертёж, молоток, шестерёнка, щит, ракета, рупор, кубок) — они
  копятся на полке под картой.
- **Контрольные точки.** Пять шлагбаумов между станциями вместо прежних gates.
- **Дверь MVP.** Открывается, когда все станции закрыты, и ведёт к сертификату.
- **Поток на карте.** Другие участники видны маленькими фигурками на своих
  позициях — видно, кто где идёт.

## Разделы кабинета

- **Карта пути** — игровой экран выше плюс полка инструментов и панель станции
- **Безопасность** — чек-лист OWASP: уровни 1–2 всем, уровень 3 (ручной аудит) — Pro/Partner; кольцо готовности к КТ-4
- **Юридический трек** — параллельная дорожка документов станций 0–7
- **Кто где идёт** — дашборд потока: аватар, позиция на треке, док, проект, ссылка на продукт
- **Стена демо** — публикация демо (+50 очков, серия ×1.1), голосование, дисклеймер о публичности
- **Лига дока** — рейтинг внутри своего дока, призы потока, правила начисления очков
- **Demo Day** — обратный отсчёт, готовность к сцене по контрольным точкам
- **Сертификат** — открывается после прохождения всех станций
- **База знаний** — материалы станций, шаблон CLAUDE.md, библиотека промптов
- **Сервисный пул** — 6 направлений + ментор; индивидуальные слоты на Pro/Partner
- **Профиль** — персонаж, проект, приватность, синхронизация с GitHub, бейджи

## Доки: лиги по сложности, а не по скорости

На старте проект проходит скрининг из семи вопросов (интеграции, регуляторика,
персональные данные, платежи, мобильный клиент, модели, роли). Сумма баллов
определяет док: **A** (≤5, лёгкий контур), **B** (≤11, средний), **C** (12+,
тяжёлый). Лига и призы считаются внутри дока — сложный проект не соревнуется с
простым.

## Приватность

Имя, аватар, станция и очки видны всему потоку — на этом держится общая карта.
Название и описание проекта показываются только при включённом публичном профиле;
иначе участники видят «проект скрыт». Переключатель — в профиле, дисклеймер
продублирован на форме сдачи демо.

## Синхронизация с GitHub

В профиле указывается публичный репозиторий (`owner/name`). Бэкенд читает
GitHub API без токенов и показывает реальную активность сборки: коммиты за 7 дней,
язык, последний коммит. Кэш — 3 минуты на участника, приватные репозитории не
запрашиваются.

## Геймификация

Очки только за проверяемые артефакты: демо +50, интервью +30, пункт ИБ +10,
контрольная точка +100, пилот/первый платёж +200, серия из 3 демо — ×1.1.
Уровень (Sketch → Captain) отражает стадию продукта, а не время в программе.

## Запуск

**С бэкендом (полноценный режим):**

```
node server/server.js        # Node ≥ 22, зависимостей нет
```

Один процесс отдаёт и API, и фронтенд: http://localhost:8787.
Аккаунты (scrypt-хэши паролей, HMAC-токены на 30 дней), прогресс, демо, голоса,
аватары и доки хранятся в SQLite (`server/data/shipyard.db`, создаётся
автоматически вместе с сид-потоком из 7 участников). Порт — env `PORT`,
секрет — env `SHIPYARD_SECRET` (иначе генерируется в `server/data/.secret`).

API: `register/login`, `me` (GET/PUT), `avatar`, `screening`, `toggle`
(задачи/ИБ/юртрек с серверной валидацией и начислением очков), `demos` + `vote`,
`flow`, `league`, `github/sync`, `certificate`, `health`.

**Без бэкенда (статика):** открыть `index.html` — фронтенд проверяет
`/api/health` и, не найдя сервер, работает на localStorage (так живёт версия
на GitHub Pages). Чтобы страница на Pages ходила в удалённый бэкенд, задайте
в `app.html` перед подключением `app.js`:
`<script>window.SHIPYARD_REMOTE_API = "https://ваш-бэкенд";</script>`

Разделы кабинета доступны по хэшу: `app.html#flow`, `#profile`, `#certificate`.
